1. **The image.** No daemon, so `Dockerfile` was checked for its properties (no `.env`, migrations
   before serve, non-root, migration step) and never built or started. **Amended 2026-11-22:**
   Appendix A re-read this row with a daemon available; the row is now `pass`. The two defects that
   re-read found are recorded there.
2. **Portability beyond the recorded platforms.** T8 records the wheel set's platforms and refuses
   a mismatch by name (`win_amd64` is refused before anything installs), but it does not make the
   packet portable: the embedded numpy wheel is macOS arm64, so a Linux auditor needs a Linux wheel
   set. The refusal is named; the capability is still per-platform.
3. **A truly air-gapped host.** Network was declared absent to the verifier and the index was made
   unreachable by configuration; the host itself still has a route. The two flags together are
   strong but are not the same observation as a physically isolated machine.

`docs/verification/2026-11-22-postgres-and-container.md` carries the readings. In summary: the
image built in 3m17s and then 57s after the fix, `autorate-portal:gate` `sha256:53b5487d5cbd…`,

Running it found two defects that reading the file could not: the build installed no extras, so
every `postgresql://` URL raised `ModuleNotFoundError: psycopg`; and with no database URL the
default relative SQLite path landed in `/app`, which the unprivileged user cannot write, so a
container with no environment failed with "unable to open database file" instead of the documented
refusal. Both are fixed, and `tests/test_dockerfile.py` now pins the four claims.
