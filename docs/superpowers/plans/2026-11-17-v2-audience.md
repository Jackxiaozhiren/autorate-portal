# V2 — The audience slice: sign in, ask a question, file the answer (2026-11-17)

One plan per slice, tasks at test-cycle size. Baseline: V1 closed at 348 tests, `serve` exists, an
offline packet replays to `612 /612`. This slice is about the people V1 could not serve: a P1/P2 who
does not run commands.

## 1. Decisions this slice is built on

| ID | Decision | Chosen | Why | Reversal |
|---|---|---|---|---|
| V2-D1 | Identity | Exchange an existing project token for a signed session cookie; no password storage | The token model already exists; adding passwords adds a credential store, reset flow and breach surface before anyone asked for it | A customer requires self-service accounts: add OIDC, not passwords |
| V2-D2 | CSRF | Double-submit cookie; session writes require `x-csrf-token`; token requests exempt | A cookie is ambient authority; a typed token is not | If the UI moves to token-per-request, the check becomes dead code and is deleted |
| V2-D3 | First screen | The claim question, not the certificate table | The table answers "what do we have"; the buyer asks "does this claim hold" | If five users cannot answer a claim in 90 s, restore the table |
| V2-D4 | Print | A4 stylesheet on the one renderer, shared by portal and self-contained document | An auditor files paper or PDF; a second template would drift | None expected |

## 2. Baseline

- 348 tests before this slice; 361 after T1–T3.
- The portal had a session *reader* and no issuer since M3: `read_session` was reachable only by a
  cookie nothing minted. T1 closes that dead path.

## 3. Tasks

### T1 — sign in (done)
1. `POST /api/v1/session` exchanges a project token for an 8-hour signed cookie naming the project.
2. The cookie carries the user's **email**, not the token's user id: the session reader resolves a
   person by email, and a cookie carrying an id fails every later request with "no such user". This
   was a real defect caught by the first test run, not a hypothetical.
3. Writes authenticated by the cookie require `x-csrf-token`; token-authenticated writes do not.
4. `DELETE /api/v1/session` clears both cookies and audits `session.revoked`.
5. Red tests: eight in `tests/test_session_login.py`, including a rejected token issuing no cookie
   and a session refusing another project.

### T2 — the question first (done)
1. The page opens on the claim form; the certificate table moves below it.
2. Copy says, in both languages, that `cannot be bounded` is a result rather than a failure.
3. Red tests: `tests/test_first_screen.py` checks source order and both catalog entries.

### T3 — a sheet an auditor can file (done)
1. The one renderer gets an A4 print block; the portal page gets one that hides its controls.
2. Red tests: `tests/test_print_view.py` renders the CLI document and reads the portal page.

### T4 — external reader walkthrough (owner action, open)
The M4 gate still asks for one P1 and one P2 who are not the author. This slice can prepare the
walkthrough and record it; it cannot name the reader. Until then the gate stays open, and no test
can close it.

### T5 — a real export drill (done)
Build `annex_iv`, `iso_42001` and `aap` bundles from the real offline packet, confirm every line
names a source, and record which headings fall back to `no evidence published`. The code path exists
and is tested on fixtures; it has never been exercised on the real artefact set.

### T6 — a monitor that actually runs (done)
`monitor` is a CLI verb and the HTTP endpoint executes inline. T6 wires one external schedule (a
cron entry is enough) and records two consecutive observations, so `not-run` and `drift` are
distinguishable in the series rather than only in tests.

### T7 — login abuse controls (conditional)
There is no rate limit on `POST /api/v1/session`. A token is 32 bytes of entropy, so guessing is not
the threat; credential stuffing against a future password flow would be. T7 waits until V2-D1 is
reopened.

## 4. Deliberately not in this slice

Password storage, self-service registration, OIDC, email delivery, per-user preferences, session
revocation lists, SSO. The session is stateless: a revoked membership takes effect on the next
request (the membership table is read every time), but a stolen cookie for an active member stays
valid until it expires. A revocation list is the fix if that becomes a requirement.

## 6. What T5 and T6 changed in the product

**`export` is now a command, not only an endpoint.** Without it the export drill could not be
run by anyone without a server, and F5 rule 4 promises a bundle a reader can re-hash alone.
`export build` and `export recheck` are the same `build_bundle`/`recheck` the endpoint calls.

**`build_bundle` no longer needs a database row.** It derived the digest and packet id from a
`db.Packet` row while both fields live on the manifest, so the CLI had nothing to pass. The
parameter is now optional; when a row *is* passed and disagrees with the manifest, the build
raises instead of picking a winner.

**`verdict_for` reads state before exit code, for two states.** The drill found that a genuine
`mismatch` was reported as `holds`: the portal computes the disagreement, so the process exits
0, and the old code trusted the exit code first. `mismatch → drift` and `refused` (no exit
code, or install sentinel 97) `→ refused` are now answered from the state. Every existing test
missed it because every one of them injected the tool's own exit 4, which the tool never emits
for this comparison.

**The monitor has a seventh verdict, `refused`.** A replay the portal stopped (integrity, pin,
platform, install) is not drift: nothing was observed, so the answer did not change. Calling it
drift would page an operator about a source that never moved — the failure mode T8 made likely
by turning platform mismatches into refusals.

Two exit-code collisions remain and are documented: `not_run` shares 3 with `not_certifiable`,
`refused` shares 4 with `drift`. Separating them means renumbering the tool's codes, which is a
protocol change.

## 7. What the reader probe (2026-11-18) changed

A machine-agent walkthrough of the live service produced
`docs/verification/2026-11-18-v2-reader-walkthrough.md` and a reproducible probe script
`docs/verification/walkthrough_probe.py`. It confirmed the V2 HTTP surface end to end and left
V2-B6 `not-run` — a machine that can execute `fetch` is not an external reader.

It also caught a regression the V1/V2 gates had missed: migration
`0005_artifact_wheel_kind` used `batch_alter_table` without a `copy_from`, so the offline
`--sql` render path (which has no connection to reflect from) failed. The migration now supplies
a reflection-free `sa.Table` mirror of 0001's artifact definition. After the fix: full suite
374 passed, `tests/test_migrations.py` 4/4, offline `--sql` emits the wheel CHECK, and a fresh
database ingests the real schema-2 packet with 2 wheel artefacts indexed.

## 8. What the visual walkthrough (2026-11-20) changed

The HTTP probe cannot see a page. A browser-agent pass over the same service (recorded in
`docs/verification/2026-11-18-v2-reader-gate.md`, Appendix A) executed the reader's clicks and
looked at the rendered result, and found two defects that no status code exposed. Both were
fixed on 2026-11-21; V2-B6 stays `not-run`, because neither fix answers whether a non-author
understands the verdict.

**Printing was unreadable under a dark system preference.** The page legitimately follows
`prefers-color-scheme` on screen, but the print block inherited it: with dark set, the computed
print colours were `color: rgb(255,255,255)` on a dark canvas, so the filed A4 sheet would have
carried white text on white paper. `@media print` now pins `color-scheme: light`, sets
`html, body { background:#fff; color:#000 }`, darkens `.muted`/`.triple` for paper, and drops the
hover tint. The self-contained document already pinned light colours and is unchanged.

**A validation error was the one English sentence on a Chinese screen.** `Claim.from_dict`
raised `ClaimError` with a fixed English message and the HTTP layer passed `str(exc)` through as
the 422 `detail`. `ClaimError` now carries the missing field names as data and exposes
`localized(locale)`; the message and the list separator are catalog entries
(`error.claim_incomplete`, `punct.list_separator`), and field names reuse the existing
`label.share|field|unit|population`. `str(exc)` remains English, so the CLI and locale-less token
API keep their wording.

Two regression tests were added — the print block must opt out of a dark preference, and the 422
must answer in the locale it was asked in. After both fixes: full suite **376 passed, 1 warning**;
the 11-step probe is unchanged (`failures: None`).
